# AI 활용 거버넌스 — 우리동네 발전소 (보고서 Ⅴ-1·Ⅴ-3)

서비스의 어느 단계에 AI가 개입하고, 어디에 사람 검증(HITL)이 들어가며,
책임 주체가 누구인지 정의한다. 스펙 §6 보안·안전 요건과의 대응을 함께 표기.

## 1. AI 개입 지점과 사람 검증 지점

| 단계 | AI 역할 | 사람(HITL) 역할 | 최종 책임 |
|---|---|---|---|
| 서비스 개발 | Claude Code로 전체 코드·데이터 파이프라인 작성 | 요구 정의, 결과 검토, 배포 승인 | 운영자 |
| 데이터 생산 (과제 A) | 공고문 크롤링 결과를 구조화(추출·분류·confidence 자가 평가) | confidence<0.85·검증 이슈 건 전수 검토(review_viewer), `apply --yes` 승인, 배포 커밋 | 운영자 |
| 데이터 검증 | 자동 규칙(금액 숫자·URL·enum·중복) + 정확도 평가(eval_accuracy) | 정답셋 유지(수동 확인 데이터), 리포트 판독, 품질 게이트(95%) 판단 | 운영자 |
| 이용자 안내 (과제 B) | 주입된 데이터 범위 안에서만 자연어 답변 | 답변은 자동 노출되지만 데이터 자체가 사람 승인분 — 원천 통제. 피드백(👍/👎) 모니터링 | 운영자 |
| 성과 측정 (과제 C) | — | GA4 지표 판독, KPI 갱신 | 운영자 |

원칙: **AI는 생산·안내, 사람은 승인·책임.** 공개 데이터에 반영되는 모든 변경은 사람 승인을 거친다.

## 2. §6 보안·안전 요건 준수 매핑

| §6 요건 | 구현 | 검증 방법 |
|---|---|---|
| ① API 키 클라이언트/저장소 노출 금지 | 파이프라인·챗봇 모두 서버(환경변수)만 사용. 클라이언트는 `/api/ask` 프록시 호출 | 저장소 전문 검색(`sk-ant` 0건), 번들 검사 |
| ② 개인정보 무수집 | 질문 원문 미저장(건수·응답시간만), IP는 해시로만 속도제한, 게시판 동일 원칙 | `ask.js`·`board.js` 코드 리뷰 |
| ③ HITL — 사람 승인 전 반영 금지 | `apply.py --yes` 게이트 + review_viewer 승인 + 수동 git 배포 | `logs/changes.log` 이력 |
| ④ 출처+기준일+변동가능 고지 | 모든 데이터에 source 필드, 챗봇 규칙 2·3, 출처·면책 모달, 상세 패널 고지 | 화면 캡처, 시연 시나리오 |
| ⑤ 공공누리 4유형 대응(원문 재배포 금지) | 원천 6종 전수 판정(docs/data_licenses.md). 재배포 불허 원천(한전 월보)은 저장소 원천 제외, 사실 수치만 출처표시 게시 | 라이선스 판정 문서 + git 추적 이력 |
| ⑥ 전력망(송전선로·변전소) 정보 금지 | 발전소·혜택 정보만 취급 — 송전선로·변전소 데이터 미수집·미표시 | 데이터 스키마(docs/data_schema.md) |
| ⑦ 비용 상한 없이 챗봇 공개 금지 | 분당 5·일 50 제한, 미설정 시 503 비활성, 콘솔 지출 한도(manual_tasks) | `ask.js` 코드 + 콘솔 설정 캡처 |

## 3. 모델·프롬프트 변경 관리

- 프롬프트는 코드와 분리해 버전 관리: `tools/ai_pipeline/prompts/structuring_prompt.md`
  (변경 이력 절 포함), 챗봇 시스템 프롬프트는 `web/api/ask.js` 내 상수(커밋 이력으로 추적).
- 모델 변경은 설정으로만: 파이프라인 `pipeline_config.yaml`, 챗봇 `CHAT_MODEL` 환경변수.
- 프롬프트·모델 변경 시 `eval_accuracy.py` 재실행으로 회귀 확인 후 반영.

## 4. 사고 대응

- 챗봇 오답·부적절 답변 신고: 소통 게시판(/board/) → 운영자가 데이터·프롬프트 수정 →
  변경 로그 기록. 심각 시 `ANTHROPIC_API_KEY` 환경변수 제거만으로 즉시 비활성(503 폴백).
- 데이터 오류: 게시판 제보 → 원문 재확인 → curated 데이터 수정 → 재배포 (기존 절차 유지).
